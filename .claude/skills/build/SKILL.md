# /build

호출 한 번에 아래 표의 세션 하나만 진행한다. 다음 세션을 이어서 시작하지 않는다.

| 세션 | 단계 | 경계 이유 |
| --- | --- | --- |
| S1 | 1~3 | 스키마·인증·공통 셸: 이후 모든 단계의 기반 |
| S2 | 4~6 | 호선·공정 계획·실적: `rules`와 공정 데이터 공유 |
| S3 | 7~8 | 도면·결재: 개정과 결재 흐름이 직결 |
| S4 | 9~10 | 회원관리·대시보드: 대시보드가 앞 단계 조회를 재사용 |
| S5 | 11 | Unity: 빌드 로그가 길고 앱 코드와 독립 |
| S6 | 12 | 최종 수용 검증: 구현 맥락 없이 검증하고 필요한 곳만 수정 |

1. **확인**: `.experiment/conditions.txt`가 없으면 초기 설정 전이므로 아무것도 바꾸지 말고 `MANUAL.md`의 초기 설정을 안내한 뒤 멈춘다. 있으면 `echo "$(date +%FT%T%z) ${CLAUDE_SESSION_ID}" >> .experiment/sessions.log`를 실행한다. `PROGRESS.md`(없으면 아래 형식으로 생성)와 `specs/index.md`를 읽고 이번 세션을 정한다. 전부 끝났으면 통과한 검증과 미확인 항목을 구분해 보고하고 멈춘다. 환경 점검 기록이 없으면 `specs/index.md`대로 수행한다.
2. **읽기**: 이번 세션 단계의 명세와 이미지만 연다. 이전 코드는 `PROGRESS.md`의 경로와 세션 시작 시 주입되는 코드맵으로 찾고 필요한 구간만 연다. `PROGRESS.md`에 있는 내용은 다시 탐색하지 않는다.
3. **구현**: 기존 코드를 재사용해 단계 순서대로 구현한다.
4. **검증**: 단계마다 관련 테스트를 실행한다. 화면이 있는 단계는 앱을 실행해 Playwright로 이미지와 비교한다. 세션 끝에 전체 테스트를 한 번 실행한다.
5. **인계**: `PROGRESS.md`를 덮어쓰고 `git add -A`를 실행한다. 코드맵이 추적 파일을 읽기 때문이다. 커밋은 하지 않는다.
6. **멈춤**: 마지막 줄에 `다음: /clear 입력 후 /build`를 출력하고 멈춘다. 세션 전환은 사용자가 입력한다.

세션 완료는 포함된 단계의 수용 기준, 관련 테스트, 화면 확인을 모두 충족한 상태다.

## PROGRESS.md

유일한 인계 기록이다. 40줄 이내로 유지하고 누적하지 말고 덮어쓴다. `.vue`는 코드맵에 나오지 않으므로 공유 컴포넌트는 여기에 적는다.

```markdown
# 인계
- 완료: S1 (단계 1~3) / 다음: S2 (단계 4~6)
- 환경: 점검 결과 한 줄, 실행 명령

## 결정·인터페이스
다음 구현에 필요한 것만: 공통 헬퍼, 공유 컴포넌트, API 형식, 테스트 픽스처

## 관련 파일
다음 세션이 열어 볼 경로

## 검증
- 통과: 항목과 건수
- 실패: 항목과 로그 경로
- 미실행: 항목과 이유

## 미해결
문제, 재현 명령, 로그 경로

## 다음 세션 첫 작업
바로 시작할 일 한 줄
```

완료 작업의 설명과 시행착오는 적지 않는다.

## 멈추는 경우

- 설치·라이선스·로그인처럼 사용자만 할 수 있는 조치가 필요하면 정확한 조치를 알리고 `PROGRESS.md`에 기록한 뒤 멈춘다. S5만 막혔다면 그 사실을 기록하고 S6으로 넘긴다.
- 세션 도중 멈췄다면 `PROGRESS.md`에 멈춘 단계를 기록한다. 대화가 살아 있으면 사용자가 `claude --continue`로 같은 세션을 재개하고, 아니면 새 세션의 `/build`가 기록된 지점부터 시작한다.
- 압축 뒤 세부가 불확실하면 추측하지 말고 `PROGRESS.md`와 현재 단계 명세를 다시 읽는다.
